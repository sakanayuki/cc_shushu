# Flick Target — DESIGN.md

## 1. 概要

スマートフォン縦持ちのWebブラウザ向け、Matter.jsを利用した物理演算フリックゲーム。

プレイヤーは画面下部の円形ディスクを直接フリックし、盤面上のターゲットへ滑らせる。ディスクは投擲後も盤面に残り、後続ディスクとの衝突によって位置が変化する。1ゲーム5投とし、5投終了時の最終配置とターゲットとの重なり率からスコアを算出する。

特殊カード、キャラクター能力、アイテム、障害物などに依存せず、「フリックの方向・強さ」「狙った位置で止める技術」「ディスク同士の物理干渉」をゲームの中心とする。

## 2. コアコンセプト

> フリックの強さと方向を身体で覚え、狙った位置にディスクを止めること自体が楽しいゲーム。

- 上達対象はキャラクターではなくプレイヤー自身のフリック技術。
- 同じ入力には可能な限り同じ結果を返し、再現性を重視する。
- 面白さは特殊効果ではなく、速度・摩擦・位置・衝突・重なりから生み出す。
- ミスしたとき「強すぎた」「弱すぎた」「右にずれた」と原因を理解できる操作感を目指す。

## 3. 対象環境

- スマートフォンWebブラウザ
- 縦持ち（Portrait）専用を基本とする
- タッチ操作前提
- HTML/CSS/JavaScript または TypeScript
- Matter.js
- Pointer Events
- Canvasベースの描画を基本候補とする

## 4. 基本画面

```text
┌─────────────────┐
│      [ 50 ]     │
│                 │
│ [30]       [20] │
│                 │
│       [10]      │
│                 │
│                 │
│        ●        │
│      DISC       │
│        ↑        │
│      FLICK      │
└─────────────────┘
```

画面上部〜中央をターゲット領域、下部を射出領域とする。

## 5. 基本ルール

1. ゲーム開始時に5個程度のターゲットを配置する。
2. 各ターゲットには基本得点を設定する。
3. プレイヤーは画面下部のディスクを直接フリックする。
4. ディスクはMatter.jsの物理演算で滑走・減速・衝突する。
5. 投げたディスクは消えず、盤面に残る。
6. 次のディスクを同じ射出領域から投げる。
7. 合計5投する。
8. 全投擲終了後、最終盤面でターゲットとの重なり率を計算する。
9. 合計得点を表示し、Retryできるようにする。

想定プレイ時間は1ゲーム30〜60秒程度。

## 6. ターゲット

ターゲットは「高得点ほど狙いにくい」というリスク・リターンを基本とする。

| 難易度 | 特徴 | 得点例 |
|---|---|---:|
| Easy | 大きい・近い | 10〜20 |
| Normal | 中サイズ・中距離 | 30〜50 |
| Hard | 小さい・遠い | 60〜100 |

完全ランダム配置にはせず、以下の制約を設ける。

- ターゲット同士を一定距離以上離す。
- 画面端から安全マージンを確保する。
- 射出領域には置かない。
- 攻略不能な配置を作らない。
- 「安全な低得点」と「難しい高得点」の複数の選択肢を作る。

## 7. フリック入力

本作で最重要の実装領域。スリングショット式ではなく、ディスクを指で直接弾く方式とする。

```text
PointerDown
    ↓
PointerMove履歴を記録
    ↓
PointerUp
    ↓
直近の移動履歴から速度・方向を推定
    ↓
正規化・クランプ
    ↓
Matter.jsのBodyへ初速を設定
```

PointerDownとPointerUpの2点だけではなく、直近数十〜100ms程度のPointerMove履歴を利用する。記録値は timestamp / x / y を基本とする。

重点調整項目：

- フリック速度の正規化
- 最小射出速度
- 最大射出速度
- 入力ノイズ除去
- 画面サイズ差・DPR差の吸収
- 指を離した瞬間の速度推定

## 8. Matter.js物理

必要な物理要素：

- 初速
- friction / frictionAir
- ディスク同士の衝突
- restitution
- 画面境界
- sleepまたは独自停止判定

基本挙動：

```text
FLICK → 初速 → 滑走 → 摩擦による減速 → 衝突 → 停止
```

プレイヤーが数回のプレイで「この距離ならこの強さ」と学習できるチューニングを優先する。現実の物理再現より、入力と結果の一貫性・納得感を重視する。

## 9. ディスクを盤面に残す

全ディスクは5投終了まで盤面に残す。これによりMatter.jsを使う意味のある物理的な戦略が生まれる。

```text
新ディスク
    ●
    ↓
    ○ ─────→ TARGET
既存ディスク
```

既存ディスクを押してターゲット中央へ移動させることも、高得点位置から誤って弾き出すこともできる。これは特殊ルールではなく、全プレイヤー・全ディスクに共通する物理法則として扱う。

## 10. 得点

「接触したか」ではなく、5投終了時のターゲットとディスクの重なり率で評価する。

```text
獲得点 = ターゲット基本点 × 重なり率
```

例：基本点50、重なり率82%なら41点。

補助的なフィードバックとして PERFECT / GREAT / GOOD / MISS を表示してもよいが、内部得点は連続値を基本とする。

目安：

- 90%以上: PERFECT
- 70%以上: GREAT
- 40%以上: GOOD
- 40%未満: MISS

## 11. 得点確定タイミング

各投擲直後には最終得点を確定しない。5投終了後の最終配置で一括計算する。

これにより、序盤に成功したディスクが後続ショットで動かされるため、最後まで結果が確定しない。

## 12. 停止判定

Matter.js上で微小速度が残り続けてゲーム進行が止まらないよう、独自の停止条件を設ける。

```text
speed < STOP_SPEED
AND
angularSpeed < STOP_ANGULAR_SPEED
が STOP_DURATION 以上継続
```

条件成立後は必要に応じて速度を0へ丸める。全ディスクが停止したら次の投擲へ進む。

## 13. スピン

初期PoCでは必須にしない。基本フリックだけで面白さが成立した後の拡張候補とする。

導入する場合、ディスク中心に対するフリック位置のオフセットから角速度を算出する。Matter.jsの円形剛体は回転だけでは進行方向が曲がらないため、カーブを採用するなら角速度に応じた微弱な横力をゲーム側で付加する。

## 14. 画面サイズ対応

CSSピクセルをそのままゲーム物理の基準にしない。論理座標系を定義し、端末の表示領域へスケーリングする。

例：

```text
Logical Width = 1000
Logical Height = viewport aspect ratioから算出
```

ディスク径、ターゲット径、フリック速度、停止距離などの体感が端末サイズによって大きく変わらないようにする。


## 19. PoC評価基準

最重要評価は以下。

> **何も追加しなくても、もう一度フリックしたくなるか。**

確認項目：

- 狙った方向へ飛ぶか。
- 強弱を意図的に使い分けられるか。
- 数回遊ぶと停止距離を学習できるか。
- ミスした理由を理解できるか。
- 高得点を狙うリスクが成立しているか。
- ディスク同士の衝突が判断を生んでいるか。
- 5投目まで緊張感が続くか。
- 終了直後にRetryしたくなるか。

## 20. 設計原則

### フリックが主役

新機能は「フリック操作を面白くするか」を基準に採否を決める。

### 結果は物理から生む

速度、摩擦、位置、衝突、重なりという少数のルールから展開を生む。

### 上達可能にする

ランダム性より再現性を優先し、プレイヤーが経験から精度を上げられるようにする。

### 失敗理由を明確にする

操作ミスとゲーム側の不確実性を混同させない。入力と結果の対応を一貫させる。

### PoCでは足さない

基本フリックが弱い状態を特殊カード、キャラクター、アイテム、演出で隠さない。まず最小構成だけで成立させる。

## 21. 理想的なプレイヤー体験

```text
「50点を狙える」
      ↓
    FLICK
      ↓
「少し強い」
      ↓
ディスクが減速
      ↓
「止まれ……」
      ↓
既存ディスクに軽く衝突
      ↓
既存ディスクがターゲット中央へ移動
      ↓
「入った！」
      ↓
次の1投でさらに良い配置を狙う
```

この「自分の入力 → 物理挙動 → 予想外だが理解可能な結果 → 次はもっと上手くできそう」という短い循環を、本作の中心的なゲームループとする。
