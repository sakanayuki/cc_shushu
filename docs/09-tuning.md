# 09. チューニングパラメータ

## 9.1 方針

**パラメータをコードに直接書かない。** すべて `src/config/params.ts` の単一オブジェクトに集約し、デバッグUIから実行時に変更できるようにする（原文 §17）。

```ts
// config/params.types.ts
export interface GameParams {
  readonly flick: FlickParams;
  readonly card: CardParams;
  readonly physics: PhysicsParams;
  readonly settle: SettleParams;
  readonly layout: LayoutParams;
  readonly board: BoardParams;
  readonly rule: RuleParams;
}
```

型を分割することで、デバッグUIのセクション分けと1対1に対応させる。

## 9.2 パラメータ一覧

### FLICK — フリック入力

| キー | 初期値 | 単位 | 範囲 | 意味 |
|---|---:|---|---|---|
| `flickPower` | 8.0 | (px/step)/(px/ms) | 1〜15 | 指の速度を初速に変換する係数 |
| `minFlickSpeed` | 22.0 | 論理px/step | 0〜30 | これ未満は投擲不成立（誤タップ保護） |
| `maxFlickSpeed` | 60.0 | 論理px/step | 20〜120 | 初速の上限 |
| `inputSampleWindowMs` | 80 | ms | 30〜200 | 速度推定に使う時間窓 |
| `peakBlend` | 0.35 | — | 0〜1 | 回帰値とピーク値のブレンド比 |
| `minSamples` | 3 | 個 | 2〜8 | 回帰に必要な最小サンプル数 |
| `maxHistory` | 32 | 個 | — | 履歴リングバッファのサイズ |

### CARD — カード寸法

| キー | 初期値 | 単位 | 意味 |
|---|---:|---|---|
| `thrownRadius` | 92 | 論理px | 投げカードの半径（全カード共通） |

投げカードの直径 184 は論理幅 1000 の約18%にあたる。実機で小さすぎたため、当初の半径46から2倍にした。

### PHYSICS — 物理

| キー | 初期値 | 範囲 | 意味 |
|---|---:|---|---|
| `linearDecel` | 0.52 | 0.05〜2 | 等加速度減速の減速量。総移動距離 = 初速² ÷ (2×この値) |
| `drag` | 0 | 0〜0.05 | 追加の指数減衰。0 なら純粋な等加速度減速 |

衝突が一切存在しないため、反発係数・摩擦・密度・反復回数のパラメータは廃止した（[05-physics.md](./05-physics.md) 5.3節）。

### SETTLE — 停止判定

| キー | 初期値 | 単位 | 意味 |
|---|---:|---|---|
| `stopSpeed` | 0.5 | 論理px/step | この速度未満を「停止中」とみなす |
| `stopAngularSpeed` | 0.02 | rad/step | この角速度未満を「停止中」とみなす |
| `stopDurationMs` | 120 | ms | 停止条件の継続時間 |
| `settleTimeoutMs` | 6000 | ms | 強制停止までのフェイルセーフ |
| `resolveDisplayMs` | 900 | ms | 判定結果の表示時間 |

### LAYOUT — 盤面レイアウト

| `logicalHeightMin` | 1600 | 論理px | 論理高さの下限 |
| `logicalHeightMax` | 2100 | 論理px | 論理高さの上限 |
| `launchOffsetY` | 190 | 論理px | 盤面下端から射出ラインまでの距離 |
| `launchZoneHeight` | 420 | 論理px | 盤面下端から射出領域上端までの距離 |
| `launchClearance` | 220 | 論理px | 射出領域上端から配置可能域下端までの距離 |

### BOARD — 盤面生成

| キー | 初期値 | 意味 |
|---|---:|---|
| `targetMinGap` | 30 | 置きカード同士の最小隙間（論理px） |
| `refillClearance` | 20 | 補充時、既存の投げカードから離す最小距離（論理px） |
| `maxPlacementAttempts` | 200 | リジェクションサンプリングの試行回数上限 |
| `gapRelaxSteps` | `[30, 15, 0]` | 試行が進んだときの `targetMinGap` の段階的緩和 |

### BOARD.slots — 難易度スロット定義

```ts
slots: [
  { difficulty: 'easy',   distMin: 0.15, distMax: 0.40, radiusMin: 80, radiusMax: 100, scoreMin: 10, scoreMax: 20 },
  { difficulty: 'easy',   distMin: 0.15, distMax: 0.40, radiusMin: 80, radiusMax: 100, scoreMin: 10, scoreMax: 20 },
  { difficulty: 'normal', distMin: 0.40, distMax: 0.70, radiusMin: 54, radiusMax: 76,  scoreMin: 30, scoreMax: 50 },
  { difficulty: 'normal', distMin: 0.40, distMax: 0.70, radiusMin: 54, radiusMax: 76,  scoreMin: 30, scoreMax: 50 },
  { difficulty: 'hard',   distMin: 0.70, distMax: 0.95, radiusMin: 36, radiusMax: 50,  scoreMin: 60, scoreMax: 100 },
]
```

`distMin` / `distMax` は射出ラインから配置可能域上端までの距離に対する比率。`radiusMin` / `radiusMax` は**半径**（論理px）であり、直径ではない。

### RULE — ルール

| キー | 初期値 | 意味 |
|---|---:|---|
| `initialHand` | 5 | 初期手札枚数 |
| `captureThreshold` | 0.5 | 獲得に必要な被覆率（厳密に超える必要がある） |
| `coverageSamples` | 10000 | 和集合の被覆率を求めるサンプル点数。重なりが2枚以上のときのみ使われる |

## 9.3 初期値の根拠

主要な値がなぜその数字なのかを記録する。**チューニング時にこの表を更新すること。** 根拠を失った数字は次の調整者を迷わせる。

### `linearDecel = 0.52`

等加速度減速では総移動距離 = `v0² / (2a)`、停止までのステップ数 = `v0 / a`。

この値は「最小初速 22 で、最も手前の置きカードに接触できる」ことから逆算した。論理高さ2100のとき射出ラインから最手前カードへの接触距離は 450論理px であり、`22² / (2×0.52) = 465` がこれをわずかに上回る。

#### 減速モデルの実測値

`linearDecel = 0.52`、固定タイムステップ 16.667ms での値。

| 初速 | 総移動距離 | 停止までの時間 |
|---:|---:|---:|
| 22（最小） | 465 | 0.71秒 |
| 26 | 650 | 0.83秒 |
| 30 | 865 | 0.96秒 |
| 35 | 1178 | 1.12秒 |
| 40 | 1538 | 1.28秒 |
| 45 | 1947 | 1.44秒 |
| 46以上 | 場外 | — |
| 60（最大） | 3462 | 1.92秒 |

盤面の実効長が約1430〜1730論理px であることから、初速40前後で最奥の Hard に到達し、**初速46以上では盤面を抜けて場外**になる。強すぎるフリックへのペナルティが機能する。

指数減衰と違い、速度は有限時間で厳密に 0 になる。末尾でじりじり滑り続けることがない。停止時間も 0.7〜1.9秒に収まり、テンポが読みやすい。

### `minFlickSpeed = 22` / `maxFlickSpeed = 60`

`minFlickSpeed` は「**有効な最弱の投擲の下限**」である。これ未満のフリックは投擲不成立となり、手札を消費しない。移動距離465論理px は、最も手前のカードに接触できる最小値にあたる。

| 論理高さ | 最手前カード中心まで | 接触に必要な距離 | 必要初速 |
|---:|---:|---:|---:|
| 1600 | 542 | 350 | 19.1 |
| 2100 | 642 | 450 | 21.6 |

盤面に収まる初速の上限は約45であり、`maxFlickSpeed = 60` はそれを大きく上回る。したがって上限にクランプされるのは「明らかに振りすぎた」場合だけで、通常プレイで天井を感じることはない。

この関係は回帰テストで固定してある（`tests/flick.test.ts` の「受理される最弱のフリックは、最も手前のカードに届く」）。配置帯や減速量を変更した際にこの前提が崩れると、テストが落ちて気づける。

### `flickPower = 8`

盤面に収まる初速の幅が 22〜45（約2.05倍）に圧縮されているため、指の速度の有効範囲は `22/8 = 2.8` 〜 `45/8 = 5.6` px/ms になる。人間が出しやすい帯の中央付近にあたる。

当初の 6 では有効範囲が 3.7〜7.5 px/ms となり、やや速すぎた。**等加速度減速への変更で初速の有効幅が狭まったことへの対処である。**

### `stopSpeed = 0.5` / `stopDurationMs = 120`

等加速度減速では速度が厳密に 0 になるため、停止判定は確実に成立する。指数減衰のときのように「いつまでも閾値を下回らない」ことがないので、継続時間を 180ms から 120ms へ短縮してテンポを上げた。

### `targetMinGap = 30`

カード寸法を2倍にしたことで盤面が混みやすくなったため、40 から 30 へ下げた。置きカード5枚（最大半径100が2枚）が配置可能域に必ず収まることを、全シードで検証している（`tests/board.test.ts`）。

### `coverageSamples = 10000`

被覆率を和集合として求める際のサンプル点数（[06-scoring.md](./06-scoring.md) 6.2節）。Vogel 螺旋による低食い違い列なので、一様乱数よりはるかに速く収束する。

重なる投げカードが1枚以下のときは解析解の経路を通るため、このコストは発生しない。決着処理は1ターンに1回しか走らないので、10000点でも体感に影響しない。

### `thrownRadius = 92`

- Easy（半径80〜100）: 投げカード1枚で約85〜100%を覆える → 安全な低得点として機能する
- Normal（半径54〜76）: 1枚で完全に覆えるが、距離があり止めるのが難しい
- Hard（半径36〜50）: 1枚で完全に覆えるが、遠く小さいので命中自体が難しい

設計上の不変条件は「投げカード1枚で閾値50%に到達できること」であり、面積比から `置きカード半径 < 92/√0.5 = 130` なら成立する。全難易度がこれを満たしている。

#### 検算: 獲得に必要な停止精度

被覆率が 50% を超えるために、投げカードの中心が置きカードの中心からどれだけ以内に止まる必要があるか。

| 難易度 | 置きカード半径 | 1枚での最大被覆率 | 獲得に必要な中心間距離 |
|---|---:|---:|---:|
| Easy | 80 | 100.0% | 79.2 以内 |
| Easy | 100 | 84.6% | 70.4 以内 |
| Normal | 54 | 100.0% | 86.5 以内 |
| Normal | 76 | 100.0% | 80.6 以内 |
| Hard | 36 | 100.0% | 89.6 以内 |
| Hard | 50 | 100.0% | 87.3 以内 |

（寸法2倍化により、従来の値をちょうど2倍したもの。比率は変わっていない）

**この表は設計上の重要な事実を示している。要求される停止精度は難易度によらずほぼ一定（70〜90論理px）であり、むしろ Hard のほうがわずかに寛容である。** 小さいカードは、投げカード1枚で覆うべき面積が小さいため、中心が多少ずれても 50% を超えられるからである。

したがって **本作の難易度は、停止精度ではなく「距離」によってほぼ全面的に決まる**。遠いほど初速の推定誤差が距離の誤差に増幅され、途中の掠りカードとの衝突リスクも増えるため、Hard が難しくなる。

この設計は原文 §6 のリスク・リターン構造を満たすが、**距離という単一の軸に依存している**点は把握しておく必要がある。プレイテストで難易度差が平坦すぎると感じた場合の調整レバーは以下の通り。

| レバー | 効果 |
|---|---|
| Hard の `distMax` を 0.95 → 1.0 に近づける | 距離差をさらに広げる（最も素直） |
| Hard の半径を 36〜50 → 24〜36 に縮める | 命中そのものを難しくする。精度要求は変わらない点に注意 |
| `captureThreshold` を 0.5 → 0.65 等に上げる | 全難易度の精度要求が一律に厳しくなる。ただしルールの説明が「過半数」でなくなる |
| Hard 帯のみ閾値を変える | 難易度差は作れるが、ルールが難易度ごとに変わり原文 §9 の「全カード共通の法則」に反する。**非推奨** |

この関係により、難易度が「面積の大小」ではなく「距離と命中精度」で決まる。原文 §6 の意図に沿いつつ、被覆率50%という一律の閾値が全難易度で意味を持つ。

## 9.4 チューニングの進め方

原文 §18 の開発優先順位に従い、以下の順で詰める。**前段が固まるまで次に進まない。**

```text
[1] フリック入力精度
    flickPower / inputSampleWindowMs / peakBlend
    → 狙った方向へ飛ぶか。強弱を意図的に使い分けられるか
        ↓
[2] 減速・停止距離
    linearDecel / flickPower / minFlickSpeed
    → 数回遊ぶと停止距離を学習できるか
    → 止まり方が「滑りすぎ」にも「急停止しすぎ」にもなっていないか
        ↓
[3] 重ねの積み上げ
    thrownRadius / captureThreshold / slots の半径
    → 2投目で狙いをずらして重ねる判断が生まれるか
        ↓
[4] 盤面バランス
    slots / targetMinGap / thrownRadius
    → 高得点を狙うリスクが成立しているか
        ↓
[5] テンポ
    stopSpeed / stopDurationMs / resolveDisplayMs
    → 待ち時間が長すぎないか
```

### シード固定での比較

チューニング中は必ず `?seed=` でシードを固定し、**同じ盤面で物理パラメータだけを変えて比較する**。毎回違う盤面で調整すると、変化が盤面差によるものかパラメータによるものか区別できず、調整が主観に堕ちる。

### 値の持ち帰り

実機で納得のいく値に到達したら、デバッグパネルの **Copy JSON** で全パラメータを取得し、`src/config/params.ts` に貼り戻してコミットする。あわせて 9.3 節の根拠表を更新する。
