# 09. チューニングパラメータ

## 9.1 方針

**パラメータをコードに直接書かない。** すべて `src/config/params.ts` の単一オブジェクトに集約し、デバッグUIから実行時に変更できるようにする（原文 §17）。

```ts
// config/params.types.ts
export interface GameParams {
  readonly flick: FlickParams;
  readonly card: CardParams;
  readonly physics: PhysicsParams;
  readonly settle: SettleParams;
  readonly layout: LayoutParams;
  readonly board: BoardParams;
  readonly rule: RuleParams;
}
```

型を分割することで、デバッグUIのセクション分けと1対1に対応させる。

## 9.2 パラメータ一覧

### FLICK — フリック入力

| キー | 初期値 | 単位 | 範囲 | 意味 |
|---|---:|---|---|---|
| `flickPower` | 6.0 | (px/step)/(px/ms) | 1〜15 | 指の速度を初速に変換する係数 |
| `minFlickSpeed` | 16.0 | 論理px/step | 0〜30 | これ未満は投擲不成立（誤タップ保護） |
| `maxFlickSpeed` | 62.0 | 論理px/step | 20〜120 | 初速の上限 |
| `inputSampleWindowMs` | 80 | ms | 30〜200 | 速度推定に使う時間窓 |
| `peakBlend` | 0.35 | — | 0〜1 | 回帰値とピーク値のブレンド比 |
| `minSamples` | 3 | 個 | 2〜8 | 回帰に必要な最小サンプル数 |
| `maxHistory` | 32 | 個 | — | 履歴リングバッファのサイズ |

### CARD — カード寸法

| キー | 初期値 | 単位 | 意味 |
|---|---:|---|---|
| `thrownRadius` | 46 | 論理px | 投げカードの半径（全カード共通） |

### BOARD.slots — 難易度スロット定義

```ts
slots: [
  { difficulty: 'easy',   distMin: 0.15, distMax: 0.40, radiusMin: 40, radiusMax: 50 , scoreMin: 10, scoreMax: 20 },
  { difficulty: 'easy',   distMin: 0.15, distMax: 0.40, radiusMin: 40, radiusMax: 50 , scoreMin: 10, scoreMax: 20 },
  { difficulty: 'normal', distMin: 0.40, distMax: 0.70, radiusMin: 27, radiusMax: 38,  scoreMin: 30, scoreMax: 50 },
  { difficulty: 'normal', distMin: 0.40, distMax: 0.70, radiusMin: 27, radiusMax: 38,  scoreMin: 30, scoreMax: 50 },
```

`distMin` / `distMax` は射出ラインから配置可能域上端までの距離に対する比率。`radiusMin` / `radiusMax` は**半径**（論理px）であり、直径ではない。

## 9.3 初期値の根拠

主要な値がなぜその数字なのかを記録する。**チューニング時にこの表を更新すること。** 根拠を失った数字は次の調整者を迷わせる。

### `frictionAir = 0.028`

指数減衰モデルでは総移動距離 ≈ `v0 / frictionAir`。

```text
初速 50 → 移動距離 1786   （盤面をちょうど縦断）
初速 30 → 移動距離 1071   （中距離のNormalに届く）
初速 15 → 移動距離  536   （近距離のEasyに届く）
```

盤面の縦の実効長（射出ライン `H-190` から配置可能域上端 `180` まで）は、論理高さ1800のとき約1430論理px。最奥の Hard（距離比率0.70〜0.95 = 約1001〜1358論理px先）に届かせるには初速 28〜38 が必要になる。

### `maxFlickSpeed = 62`

盤面縦断に必要な初速が約50であるのに対し、23%の余裕を持たせた値。**全力で振れば上端を越えて場外に飛び出せる**設定であり、決定8（上端のロスト）のペナルティを物理的に成立させる。

同時に、通常のプレイでは上限に当たらないため「強く振っても同じ」という天井を感じない。

### `minFlickSpeed = 16`

**この値は実装時に 8 から改めた。** 当初の 8 は移動距離にして約274論理px だが、射出ラインから最も手前の Easy カードに接触するには約546論理px（論理高さ2100時）必要であり、「受理されるが何にも届かず、確実に手札を1枚失う投擲」が存在していた。実ブラウザでの動作確認でこの状態が実際に再現された。

16 は移動距離約559論理px にあたり、端末サイズによらず最も手前のカードに接触できる。

| 論理高さ | 最手前カード中心まで | 接触に必要な距離 | 必要初速 |
|---:|---:|---:|---:|
| 1600 | 567 | 471 | 13.5 |
| 2100 | 642 | 546 | 15.6 |

これにより `minFlickSpeed` の意味が「誤タップ保護」から「**有効な最弱の投擲の下限**」へと明確になった。これ未満のフリックは投擲不成立となり、手札を消費しない。

この関係は回帰テストで固定してある（`tests/flick.test.ts` の「受理される最弱のフリックは、最も手前のカードに届く」）。配置帯や摩擦を変更した際にこの前提が崩れると、テストが落ちて気づける。

### `restitution = 0.35`

投げカード同士が「コツン」と当たって双方が動く値。

- 0.0 付近: 当たったカードがその場で止まり、押し出しが弱い。戦術が生まれない
- 0.6 以上: 弾かれすぎて予測が難しく、原文 §20 の予測可能性を損なう

### `wallRestitution = 0.20`

壁に当たったカードが弱く跳ね返り、壁際の何もない位置で止まる。「強すぎた」ことが結果として現れる。高くすると跳ね返りで盤面中央に戻ってきてしまい、ペナルティが消える。

### `stopSpeed = 0.35`

このあたりの速度では、1秒間の移動距離が10論理px未満（画面上で数ピクセル）となり、目視ではほぼ静止して見える。これより小さくすると停止待ちが体感的に長くなり、テンポを損なう。

### `targetMinGap = 40`

投げカードの直径は92。置きカード同士の隙間が40あれば、1枚の投げカードが2つの置きカードに大きく重なることは起きにくい。完全には排除しないため、「2つの中間を狙って両取りを試みる」という高度な選択肢は残る。

### 減速モデルの実測値

`frictionAir = 0.028`、固定タイムステップ 16.667ms でシミュレートした実測値。

| 初速 | 総移動距離 | 停止までの時間 |
|---:|---:|---:|
| 16（最小） | 559 | 2.25秒 |
| 15 | 524 | 2.22秒 |
| 30 | 1059 | 2.62秒 |
| 40 | 1416 | 2.78秒 |
| 50 | 1773 | 2.92秒 |
| 62（最大） | 2202 | 3.05秒 |

盤面の実効長が約1430論理px（論理高さ1800時）であることから、初速40で最奥に到達し、初速62では盤面を約770px 超過して**場外へ抜ける**。決定8のペナルティが機能する設計になっていることが確認できる。

停止までの時間が初速によらず 1.8〜3.1秒の範囲に収まるのは指数減衰の性質である。`settleTimeoutMs = 6000` は最大値 3.05秒の約2倍であり、フェイルセーフとして妥当な余裕がある。

### `thrownRadius = 46`

- Easy（半径40〜50）: 投げカード1枚で約85〜100%を覆える → 安全な低得点として機能する
- Normal（半径27〜38）: 1枚で完全に覆えるが、距離があり止めるのが難しい
- Hard（半径18〜25）: 1枚で完全に覆えるが、遠く小さいので命中自体が難しい

いずれの難易度でも置きカードの半径が投げカードの半径 46 以下に収まっており、**1枚で閾値50%に到達できる**ことが保証されている。

#### 検算: 獲得に必要な停止精度

被覆率が 50% を超えるために、投げカードの中心が置きカードの中心からどれだけ以内に止まる必要があるか。

| 難易度 | 置きカード半径 | 1枚での最大被覆率 | 獲得に必要な中心間距離 |
|---|---:|---:|---:|
| Easy | 40 | 100.0% | 39.6 以内 |
| Easy | 50 | 84.6% | 35.2 以内 |
| Normal | 27 | 100.0% | 43.2 以内 |
| Normal | 38 | 100.0% | 40.3 以内 |
| Hard | 18 | 100.0% | 44.8 以内 |
| Hard | 25 | 100.0% | 43.7 以内 |

**この表は設計上の重要な事実を示している。要求される停止精度は難易度によらずほぼ一定（35〜45論理px）であり、むしろ Hard のほうがわずかに寛容である。** 小さいカードは、投げカード1枚で覆うべき面積が小さいため、中心が多少ずれても 50% を超えられるからである。

したがって **本作の難易度は、停止精度ではなく「距離」によってほぼ全面的に決まる**。遠いほど初速の推定誤差が距離の誤差に増幅され、途中の掠りカードとの衝突リスクも増えるため、Hard が難しくなる。

この設計は原文 §6 のリスク・リターン構造を満たすが、**距離という単一の軸に依存している**点は把握しておく必要がある。プレイテストで難易度差が平坦すぎると感じた場合の調整レバーは以下の通り。

| レバー | 効果 |
|---|---|
| Hard の `distMax` を 0.95 → 1.0 に近づける | 距離差をさらに広げる（最も素直） |
| Hard の半径を 18〜25 → 12〜18 に縮める | 命中そのものを難しくする。精度要求は変わらない点に注意 |
| `captureThreshold` を 0.5 → 0.65 等に上げる | 全難易度の精度要求が一律に厳しくなる。ただしルールの説明が「過半数」でなくなる |
| Hard 帯のみ閾値を変える | 難易度差は作れるが、ルールが難易度ごとに変わり原文 §9 の「全カード共通の法則」に反する。**非推奨** |

この関係により、難易度が「面積の大小」ではなく「距離と命中精度」で決まる。原文 §6 の意図に沿いつつ、被覆率50%という一律の閾値が全難易度で意味を持つ。

## 9.4 チューニングの進め方

原文 §18 の開発優先順位に従い、以下の順で詰める。**前段が固まるまで次に進まない。**

```text
[1] フリック入力精度
    flickPower / inputSampleWindowMs / peakBlend
    → 狙った方向へ飛ぶか。強弱を意図的に使い分けられるか
        ↓
[2] 摩擦・停止距離
    frictionAir / maxFlickSpeed
    → 数回遊ぶと停止距離を学習できるか
        ↓
[3] 衝突の気持ちよさ
    restitution / density
    → 押し出しが意図通りに起きるか
        ↓
[4] 盤面バランス
    slots / targetMinGap / thrownRadius
    → 高得点を狙うリスクが成立しているか
        ↓
[5] テンポ
    stopSpeed / stopDurationMs / resolveDisplayMs
    → 待ち時間が長すぎないか
```

### シード固定での比較

チューニング中は必ず `?seed=` でシードを固定し、**同じ盤面で物理パラメータだけを変えて比較する**。毎回違う盤面で調整すると、変化が盤面差によるものかパラメータによるものか区別できず、調整が主観に堕ちる。

### 値の持ち帰り

実機で納得のいく値に到達したら、デバッグパネルの **Copy JSON** で全パラメータを取得し、`src/config/params.ts` に貼り戻してコミットする。あわせて 9.3 節の根拠表を更新する。
