# 02. ゲームルール仕様

## 2.1 用語定義

本設計書では以下の用語を厳密に使い分ける。実装時の識別子もこれに従う。

| 用語 | 英名 / 識別子 | 定義 |
|---|---|---|
| 置きカード | `PlacedCard` | 盤面に置かれている得点対象。円形。静的センサー（動かない・衝突しない）。常に5枚 |
| 投げカード | `ThrownCard` | プレイヤーがフリックして盤面に放ったカード。円形。物理ボディ。投げカード同士は衝突する |
| 手札 | `hand` | まだ投げていない投げカードの枚数。初期5枚 |
| 被覆率 | `coverage` | ある置きカードについて、重なる全投げカードの重なり面積の合計 ÷ その置きカードの面積 |
| 獲得 | `capture` | 被覆率が 50% を超えた置きカードを取得すること |
| 回収 | `collect` | 獲得時に、置きカードとそれに重なっていた投げカードを盤面から取り除くこと |
| 空振り | `whiff` | 停止時にどの置きカードにも重なっていない投げカード |
| 掠り | `graze` | 置きカードに重なっているが被覆率が 50% 以下で、盤面に残る投げカード |
| ロスト | `lost` | 盤面上端を越えて場外に出た投げカード |
| 射出ライン | `LAUNCH_Y` | 投げカードが射出される Y 座標（論理座標） |
| ロストライン | `y = 0` | 盤面上端。これを越えた投げカードは失われる |


## 2.3 ゲームルール

1. ゲーム開始時、置きカードを5枚配置する（難易度スロット Easy2 / Normal2 / Hard1）
2. 各置きカードには出現時に**難易度帯内でランダムな得点**が割り当てられる
3. プレイヤーの手札は5枚から始まる
4. プレイヤーは画面下部の射出領域内のどこかに触れてフリックする
5. 触れた X 座標に投げカードがスナップし、射出ライン上から発射される。手札が1枚減る
6. 投げカードは Matter.js の物理演算で滑走・減速し、既存の投げカードと衝突する
7. 盤面上端を越えた投げカードはロストし、失われる
8. **全カードが停止したら**、判定処理（2.4）を実行する
9. 手札が0枚になった時点でゲーム終了。累計得点を表示し、Retry できる

## 2.4 判定処理（決着処理）

全カード停止後、**必ずこの順序で**処理する。順序が入れ替わると結果が変わるため、実装上も固定する。

```text
[1] 獲得判定
    各置きカードについて、
      coverage = Σ(重なる投げカードとの重なり面積) ÷ 置きカードの面積
    coverage > 0.5 なら獲得
        ↓
[2] 回収
    獲得された置きカードを盤面から除去し、得点を加算
    その置きカードに重なっていた投げカードをすべて盤面から除去し、手札に戻す
        ↓
[3] 空振り除去
    [2] で回収されなかった投げカードのうち、
    どの置きカードにも重なっていないものを盤面から除去する（手札には戻らない＝失われる）
        ↓
[4] 掠り残留
    置きカードに重なっているが獲得に至らなかった投げカードは、そのまま盤面に残る
        ↓
[5] 補充
    [2] で空いた難易度スロットごとに、位置・径・得点を再計算して新しい置きカードを配置する
        ↓
[6] 終了判定
    手札が0枚なら GAMEOVER、そうでなければ次の投擲へ
```

### 判定処理の設計意図

- **[1] が面積合計である理由**: 投げカード同士は剛体なので物理的に重なれない。したがって複数枚の重なり面積を単純加算しても、和集合面積と厳密に一致し、二重計上が原理的に起きない。この性質により「もう1枚寄せて取る」という逆転が、幾何学的な破綻なく成立する
- **[2] で投げカードが手札に戻る理由**: 成功が「次の投擲権」に直結し、上手いプレイヤーほど長く遊べる構造を作るため
- **[3] で空振りが失われる理由**: 「何かに重ねる」ことを明確な目標にするため。完全に外すと手札を1枚失うので、弱く投げても強く投げても「触れさえすれば残る」という指針が生まれる
- **[4] で掠りが残る理由**: 次の投擲で押して被覆を増やすという、§9 の物理干渉を得点に直結させるため

### 判定処理の重要な性質

| 性質 | 内容 |
|---|---|
| 手札の上限 | カード総数（手札＋盤面の投げカード）は空振りとロストでのみ減る単調減少列。よって手札が初期5枚を超えることはなく、上限管理は不要 |
| ゲームの有限性 | 空振りまたはロストが起きるたびにカード総数が減るため、ゲームは必ず有限手で終了する |
| 獲得の不可逆性 | 一度獲得した得点は後続の投擲で失われない |
| 連鎖獲得 | 1回の投擲で複数の置きカードが同時に獲得されうる（衝突で既存の掠りカードが押されて複数箇所で過半数に到達した場合） |

## 2.5 ゲーム状態機械

```text
        ┌──────────────────────────────────────┐
        │                                      │
        ▼                                      │
     [BOOT] ──► [READY] ──pointerdown──► [AIMING]
                   ▲                          │
                   │                     pointerup
                   │                          │
                   │                          ▼
                   │                      [FLYING]
                   │                          │
                   │                 全カード停止 or タイムアウト
                   │                          │
                   │                          ▼
                   │                     [RESOLVING]
                   │                          │
                   │                 判定処理 [1]〜[5]
                   │                          │
                   │            ┌─────────────┴──────────────┐
                   │        手札 > 0                      手札 = 0
                   │            │                            │
                   └────────────┘                            ▼
                                                         [GAMEOVER]
                                                              │
                                                          Retry
                                                              │
                                                              ▼
                                                          [READY]
```

| 状態 | 説明 | 入力受理 | 物理更新 |
|---|---|---|---|
| `BOOT` | 初期化（Canvas、Matter.js、盤面生成） | なし | なし |
| `READY` | 投擲待ち。待機カードが射出ライン中央に表示される | PointerDown を受理 | あり（掠りカードは静止済み） |
| `AIMING` | 指が接地しており、PointerMove 履歴を記録中 | PointerMove / PointerUp / PointerCancel | あり |
| `FLYING` | 投げカードが滑走中 | 受理しない（次の投擲は不可） | あり |
| `RESOLVING` | 判定処理と被覆率表示、回収アニメ | 受理しない | 停止（または低速再生） |
| `GAMEOVER` | リザルト表示 | Retry ボタンのみ | 停止 |

### 状態遷移の補足

- `AIMING` 中に `pointercancel` が発生した場合、投擲は成立せず `READY` に戻る。手札は減らない
- `AIMING` 中に推定速度が `MIN_FLICK_SPEED` 未満だった場合も、投擲は成立せず `READY` に戻る（誤タップ保護）。手札は減らない
- `FLYING` は `SETTLE_TIMEOUT_MS`（初期6000ms）を超えたら強制的に全カードの速度を0に丸めて `RESOLVING` へ遷移する。これは Matter.js 上で微小速度が残り続けてゲーム進行が止まる事態へのフェイルセーフである
- `RESOLVING` の表示時間は `RESOLVE_DISPLAY_MS`（初期900ms）。この間に被覆率が表示され、獲得カードの回収アニメが再生される

## 2.6 得点

- 累計得点 = 獲得した置きカードの得点の総和
- 部分点はない。被覆率 50% 以下は 0 点
- 得点は整数値のみを扱う
- ベストスコアは `localStorage` に保存し、リザルト画面に表示する

### 得点表

**寸法はすべて半径で表記する**（直径と混同すると獲得可能性が変わるため、実装上も `radius` に統一する）。

| 難易度 | 半径（論理px） | 射出ラインからの距離 | 得点範囲 |
|---|---|---|---:|
| Easy | 40 〜 50 | 近 | 10 〜 20 |
| Normal | 27 〜 38 | 中 | 30 〜 50 |
| Hard | 18 〜 25 | 遠 | 60 〜 100 |

投げカードの半径は 46 で固定。1枚で覆える面積は `π × 46² ≒ 6648`。したがって：

- **Easy**（半径40〜50、面積5027〜7854）は投げカード1枚で 85〜100% を覆える。安全な低得点
- **Normal**（半径27〜38、面積2290〜4536）は1枚で完全に覆えるが、距離があり止めるのが難しい
- **Hard**（半径18〜25、面積1018〜1963）も1枚で完全に覆えるが、遠く小さいので命中させること自体が難しい

**置きカードの半径は投げカードの半径（46）を超えないように設定する。** 超えると1枚では 50% に届かなくなり、複数枚を寄せない限り獲得できないカードが生まれてしまう。Easy の上限 50 はこれにわずかに抵触するが、半径50のカードに対する1枚の最大被覆率は `46²/50² = 84.6%` であり、閾値 50% を大きく上回るため問題にならない。

この関係により、原文 §6 の「高得点ほど狙いにくい」というリスク・リターン構造が、面積の大小ではなく**距離と命中精度**によって成立する。
